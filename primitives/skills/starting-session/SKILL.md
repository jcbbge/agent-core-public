# Starting Session

Starting is re-centering, not running a checklist. The point is to be connected to
the operator, the current project and the work in front of us. The conditions below
can be established in whatever way the context calls for; they are not an execution order.

## Continuity is present

Circadian memory is part of every start. Understand the relevant context already
supplied, and use targeted recall where continuity is missing. Do not repeat retrieval
or recite memory merely to demonstrate that it happened.

When Graphiti is available through an existing usable interface, bring its relevant
project relationships and history into the picture too. A configured name is not proof
of access. If memory is unavailable, say what continuity is missing rather than
pretending to remember or turning orientation into an infrastructure-repair task.

Memory explains how we got here. It is context, never a mandate that overrides the
operator's present intent or evidence of the project's current state.

## We share the present intent

There is an understanding of what this project or domain is for, what matters now,
what the operator is asking, and what role this session plays. Discussion, exploration,
a decision and implementation are not interchangeable permissions.

Use context already given instead of asking the operator to reconstruct it. Make
material ambiguity visible; do not fill it with a plausible story.

## We have sound footing

Distinguish present reality from remembered or handed-off state: what exists, what
has changed, what is underway, whose work it is, and what must remain untouched.
The repository and any active delivery system hold work state; memory must not become
a competing ledger. Existing unfinished work is context, not an invitation to clean up.

Technical investigation belongs to the actual task. Know enough to choose the next
useful move or question without assuming unknown contracts, interfaces or constraints.
No particular command, script, service, status report or directory ritual establishes this.

## We know what the machine is holding

Work leaves things standing: worktrees, branches, stashes, databases, running servers,
containers. Know what this machine holds for the project and what each is for. Where
the project has a task lifecycle, its entrypoint names the ledger; read that rather than
inferring from directory listings.

Everything standing is one of three things. In progress is someone's live work: leave it.
Landed means its work is in the trunk: reap it through the project's own teardown, which
stops what it runs before removing it. Abandoned is unmerged and idle: the operator
decides. Judge landed by the work being in the trunk, not by a branch name, and not by
ancestry alone; a branch that was only fast-forwarded along the trunk carries no work.
Reaping what has landed is the one cleanup a start does.

## The next move fits

The next action or question follows from the current intent and actual authority.
Proceed with clearly named, authorized work; stay in conversation when that is the work.
Do not reopen settled choices or ask for an objective the operator already supplied.
Follow the environment's existing global and project workflow rather than duplicating it.

## A small acknowledgement is enough

Signal connection with a brief, natural acknowledgement: the equivalent of a head nod.
No fixed phrase, context recitation, dashboard or ceremonial orientation is required.
When a real gap matters, surface that gap instead of claiming alignment we do not have.
